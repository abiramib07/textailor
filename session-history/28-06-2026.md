## 2. Pending-Edits Feature (Drop Zone)

**Purpose:** A permanent designated place to paste raw project/edit content. The agent reads it, asks Claude to analyse, asks the user for confirmation in the terminal, patches `resume/main.tex`, and archives the processed edit.

| File / Folder | Role |
|---|---|
| `inputs/pending-edits.md` | Drop zone — paste raw content here |
| `inputs/processed/` | Auto-archive of applied edits (YYYY-MM-DD-slug.md) |
| `inputs/backups/` | Numbered backups of main.tex before each change (v1.tex, v2.tex …) |
| `src/agents/editor.py` | Agent: read → analyse → confirm → patch → archive → clear |

**Pipeline integration:** `src/main.py` calls `apply_pending_edits(config)` as Step 0 before every JD run.

## 3. Chat Editor Feature

**Purpose:** After viewing the generated PDF, type natural language instructions to tweak the resume. Two-phase: plan shown first → user confirms → execute.

**Phase 1 — Plan:** `POST /api/chat/plan` → Claude reads message + `main.tex` → returns plain-English summary + bullet list of changes. Zero file writes.

**Phase 2 — Execute:** `POST /api/chat/execute` → Claude generates minimal LaTeX patches → validates all `old` strings exist → backup → apply → compile. Auto-reverts if pdflatex fails.

**Undo:** `POST /api/chat/undo` → restores latest `inputs/backups/vN.tex` → recompiles.

Files: `src/agents/chat_editor.py`, 4 new routes in `src/api.py`, full chat state machine in `ui/src/app/app.ts` and `app.html`.

## 8. Bug Fixes (Second Session)

All bugs discovered during testing were fixed and logged in `issue-log.md`. Summary:

### Bug 1 — `! Misplaced alignment tab character &` (Critical pipeline crash)
`resume/main.tex` had `P&L` unescaped in two `\bulletitem{}` lines. LaTeX treats `&` as table-column separator — illegal in text mode.  
**Fix:** `P&L` → `P\&L` in source. Rewriter prompt now includes escaping rule. `_escape_ampersands()` post-processing added as safety net.

### Bug 2 — Parser + Patcher used `\header{}`, resume uses `\section{}` (Silent total failure)
`latex_parser.py` and `latex_patcher.py` both looked for `\header{Name}` markers. The resume uses `\section*{Name}` and `\section{Name}`. Result: `extract_sections()` returned empty dict → nothing rewritten → tailored PDF was identical to original.  
**Fix:** Both files updated to use `\\section\*?\{...\}` regex.

### Bug 3 — ATS score always 0.0% (Two compounding causes)
1. `config.json` had wrong section names (`Career Objective`, `Projects`, `Skills`) that don't exist in `main.tex` — only `Experience` was rewritten.
2. Scoring was done against only the rewritten sections text, not the full resume — keywords in Technical Skills and Summary were never checked.  
**Fix:** `config.json` corrected to `["Professional Summary", "Technical Skills", "Experience"]`. Scoring now uses `strip_latex(patch_tex(raw_tex, rewritten, sections))` — the full patched resume.

### Bug 4 — Template preview blank / PDF auto-downloads (Content-Disposition: attachment)
`FileResponse(filename="...")` sets `Content-Disposition: attachment` causing browsers to download instead of displaying inline in an iframe.  
**Fix:** All `FileResponse` calls now use `headers={"Content-Disposition": "inline"}`. Template endpoint also recompiles if `main.tex` is newer than `main.pdf` (was serving stale PDF).

### Bug 5 — PDF font rendering not crisp
**Fix:** Added `\usepackage[protrusion=true,expansion=true,final]{microtype}` to `resume/main.tex`.
