## Work Done

### 1. Bug fixes carried over from login-module work
- **"Login failed" on non-4200 origins** — root cause was CORS `allow_origins`
  hardcoded to `localhost:4200`; browsers reaching the app through an IDE
  port-forwarding proxy (e.g. `localhost:49171`) got silently blocked at the
  preflight. Switched to `allow_origin_regex` matching any
  `localhost`/`127.0.0.1` port instead of a fixed allow-list.
- **"Lonely \item" pdflatex crash** — the rewriter agent occasionally
  appended a markdown "notes" commentary block after its LaTeX output,
  containing a backtick-quoted `` `\item` `` that LaTeX parsed as a real
  command outside any list environment. Fixed with a stricter prompt plus a
  defensive `_strip_leaked_commentary()` post-processor in
  `src/agents/rewriter.py` that truncates at the first sign of leaked
  markdown.

### 2. Project coding-standards rule
Wrote **`CLAUDE.md`** — loaded automatically every session — codifying that
all code must pass `ruff`/`mypy` (backend) and `ng lint`/`ng build` (strict
TypeScript, frontend) before being considered done, documenting the current
file/folder conventions, and explicitly noting that existing files
(`api.py` in particular) shouldn't be restructured without being asked.

### 3. Full coding-standards pass (backend + frontend)
- **Backend**: added `pyproject.toml` (ruff + mypy config). Added missing
  module/function/class docstrings and type hints across all 27+ source
  files (verified zero gaps via `ruff --select D`). Fixed real bugs the
  linters caught along the way: unsorted imports, bare `raise` losing
  exception chains, an unused import, a loop-variable closure bug in
  `latex_patcher.py`, a stray mid-file `import re` in `main.py`, a
  `Path`/`str` type conflation in `compiler.py`, an implicit-`Optional`
  default, an untyped cookie `samesite` literal. Removed one dead
  (unused) Pydantic model.
- **Frontend**: enabled TypeScript `strict` + Angular `strictTemplates`
  (surfaced only one trivial warning). Added ESLint via `@angular-eslint`
  (only Prettier existed before), wired to `ng lint`. Ran Angular's
  official codemods — `@if`/`@for` control-flow migration (replacing every
  `*ngIf`/`*ngFor`) and `inject()` migration (replacing constructor
  injection) — across the whole app. Manually fixed the remaining
  accessibility findings: invalid nested `<label>` markup → proper
  `for`/`id` pairing, non-focusable clickable `<div>`s → real `<button>`
  elements, removed an `autofocus` attribute in favour of programmatic
  focus, added Escape-key handling as the keyboard alternative to two
  click-outside-to-dismiss backdrops.
- Verified live afterward: full signup → OTP → PIN → logout → login →
  Resume Editor → History → Email Generator flow, zero console errors,
  pixel-identical visuals to before the pass.

### 5. Phase 2 — email pattern-learning (corrected scope)
Clarified with the user that "voice learning" actually means: capture every
chat revision instruction ("make it shorter", "more formal tone", …) as a
learned pattern, and auto-apply the accumulated patterns to future email
generations — not learning from separately-approved emails. Implemented
`src/email_patterns.py` (simple append-only SQLite log) and wired it into
`/api/email/revise` (writes) and `/api/email/generate` (reads the 15 most
recent patterns and folds them into the generation prompt).

### 6. Phase 2 — Career Tools module (backend)
New `src/career/` package (`db.py`, `schemas.py`, `router.py`,
`topic_mapping.py`), mirroring the existing `auth/` module's structure,
covering:
- **Personal info clipboard** — key/value store (LinkedIn URL, GitHub URL,
  email, phone, short pitch, + custom fields).
- **Apply-later queue** — URL + company + notes + applied flag.
- **LinkedIn/job-post archive** — URL, company, role, pasted text, plus
  multiple screenshot attachments per post (paste-from-clipboard upload,
  10 MB cap, image-mimetype validation, stored on disk with the DB holding
  just the path).
- **Interview-prep checklist** — per-company topics with covered state,
  GitHub link, YouTube link, notes.
- **JD topic mapping** — auto-logs every required/preferred keyword from
  every JD analysed by the existing pipeline (no manual entry), bucketed
  by a regex-parsed years-of-experience heuristic (0-2 / 3-5 / 5+ /
  unspecified), aggregated by frequency for the "what do companies keep
  asking for" view.

All 13 new endpoints exercised directly via FastAPI's `TestClient`
(personal info, apply-later CRUD, job-post + attachment upload, interview
topics, topic-map aggregation) — all correct; test data cleaned out of the
real database afterward. `ruff`/`mypy` clean.

### 7. Phase 2 — Career Tools module (frontend)
Five new standalone components under `ui/src/app/career/`, grouped behind
a new **"Career Tools ▾"** dropdown in the topbar (Escape-key dismissible,
same click-outside pattern as the existing history sidebar): Personal
Info, Apply Later, LinkedIn Archive, Interview Prep, Topic Mapping. Shared
`career.service.ts` for all API calls. `ng build`/`ng lint` clean on the

### 8. Bug found + fixed: Email Generator lost state on tab switch
While addressing "can I run the resume generator and email generator at
the same time" — confirmed both already run concurrently server-side
(resume pipeline in its own thread, email generation in FastAPI's
threadpool since it's a sync `def`), but found the Email Generator
component was `@if`-destroyed whenever the user switched tabs, silently
discarding any in-progress or just-completed generation. Fixed by keeping
`<app-email-generator>` permanently mounted and toggling visibility via a
`.tab-hidden` CSS class instead of structural removal — matches how the
main Generator tab's state already survived (that one lives in the parent
component, not a child destroyed by `@if`).
